# Telegram-бот «Что не даёт вам нормально отдыхать вечером?»

Бот проводит тест из пяти вопросов, показывает результат, собирает **с явного согласия**
логин пользователя в Telegram и даёт администратору рассылку по базе — как массовую,
так и персональную.

Написан на Go, зависимость одна: `go-telegram-bot-api/v5`.

## Что умеет

**Пользователь**

| Команда | Действие |
|---|---|
| `/start` | Приветствие и кнопка запуска теста |
| `/test` | Пройти тест заново |
| `/mydata` | Что бот о вас хранит (`/mystats` тоже работает) |
| `/forget` | Отозвать согласие и удалить данные (`/unsubscribe` тоже работает) |
| `/privacy` | Как бот обращается с данными |
| `/help` | Справка |

Тест: 5 вопросов, ответы кнопками `1/2/3` либо текстом (`1/2/3`, `А/Б/В`).
После результата кнопка практики («Начать свою паузу сейчас» и др.) присылает аудио `assets/practice.mp3` прямо в чат.

**Меню команд разделено.** При запуске бот настраивает меню Telegram: обычные пользователи видят
только пользовательские команды, администраторы из `ADMIN_IDS` — ещё и админские.
Админские команды у остальных не работают, даже если набрать их вручную.
Если меню админа не появилось, напишите боту `/start` и перезапустите бота.
Индикатор прогресса — в тексте вопроса: `Вопрос 2 из 5`.

**Администратор** (`ADMIN_IDS`)

| Команда | Действие |
|---|---|
| `/admin` | Справка по админ-командам |
| `/stats` | Сколько тестов пройдено, сколько подписчиков, распределение результатов |
| `/users` | Подписчики: имя, логин, телефон (если оставили), результат |
| `/broadcast` | Рассылка подписчикам: текст → предпросмотр → отправка |
| `/send <ID> <текст>` | Личное сообщение конкретному пользователю |

Рассылка идёт с паузой между сообщениями (`BROADCAST_DELAY_MS`), чтобы не упереться
в лимиты Telegram. Получают её только те, кто дал оба согласия.

## Логика подсчёта

Соответствие вариантов категориям одинаково во всех пяти вопросах:

| Вариант | Категория | Что отражает |
|---|---|---|
| 1 (A) | `WorkInHead` | Работа продолжается в мыслях |
| 2 (B) | `AutoFill` | Пауза автоматически заполняется занятиями |
| 3 (C) | `PostponedRest` | Отдых откладывается до сильной усталости |

Правила:

- каждый ответ даёт 1 балл своей категории, пропуск — не даёт ничего;
- побеждает категория с максимальным баллом;
- при равенстве максимумов показываются **все** победившие категории, без случайного выбора;
- если отвечено меньше трёх вопросов — вместо результата выводится
  «Ответов пока недостаточно, чтобы выделить тенденцию».

Буквы A/B/C пользователю не показываются: они остаются только в логике подсчёта,
как и просит ТЗ.

## Картинки

Каждая настройка ниже принимает путь к файлу, https-ссылку или `file_id` Telegram. Локальный файл загружается в Telegram один раз, а дальше бот отправляет его по `file_id`.

| Где показывается | Переменная | По умолчанию |
|---|---|---|
| Приветствие | `WELCOME_PHOTO` | `assets/welcome.jpg` |
| Вопрос N (1–5) | `QUESTION_PHOTO_N` | `QUESTION_PHOTO`, затем `assets/question_N.jpg` или `.png` |
| Результат: преобладает ответ 1 | `RESULT_PHOTO_1` | `assets/result_1.jpg` или `.png` |
| Результат: преобладает ответ 2 | `RESULT_PHOTO_2` | `assets/result_2.jpg` или `.png` |
| Результат: преобладает ответ 3 | `RESULT_PHOTO_3` | `assets/result_3.jpg` или `.png` |
| Результат: равенство баллов | `RESULT_PHOTO_TIE` | `assets/result_tie.jpg` или `.png` |

Проще всего положить в `assets/` файлы `question_1.jpg` … `question_5.jpg` и `result_1.jpg`, `result_2.jpg`, `result_3.jpg`, `result_tie.jpg`: тогда настраивать ничего не нужно.
Текст результата длиннее 1024 символов, поэтому картинка результата приходит отдельным сообщением прямо перед ним.
Текст вопроса становится подписью к картинке; лимит подписи в Telegram — 1024 символа.
Если картинка не отправилась, бот пришлёт вопрос обычным текстом.

## Персональные данные и 152-ФЗ

Порядок в боте:

1. Результат показывается сразу, ничего не запрашивая (как в ТЗ).
2. Практика приходит прямо в чат (`PRACTICE_AUDIO` или `PRACTICE_URL`). Контакт для доставки не нужен.
3. Через час после практики бот спрашивает «Получилось прослушать или нет?» с кнопками «Да» / «Нет».
4. На «Нет» бот напоминает через 6 часов и через сутки (от момента ответа).
5. Через час после «Да» бот предлагает подписку: кнопки «✅ Согласен», «📄 Пользовательское соглашение» (текст показывается только по нажатию) и «Нет, спасибо». «Согласен» — согласие на рассылку и на обработку ПДн, затем бот просит номер телефона кнопкой Telegram (`COLLECT_PHONE`, по умолчанию включено; можно пропустить, принимается только собственный номер).
6. При отказе на любом шаге в файл ничего не записывается.

Имя и @логин бот берёт из профиля Telegram, вручную их не вводят.
Как доказательство согласия хранятся время, редакция текста (`consent_version`) и способ (`consent_method`).
Команда `/mydata` показывает пользователю всё, что о нём сохранено. Команда `/forget` отзывает согласие и сразу удаляет данные.
Рассылка уходит только подписчикам, в конце каждого сообщения есть ссылка на отписку.
Профили автоматически удаляются через `DATA_RETENTION_DAYS` после последнего обновления.
Про тех, кто не подписался, хранится только обезличенный счётчик прохождений.

Что должен сделать оператор (кодом это не решить): см. [docs/PRIVACY.md](docs/PRIVACY.md).

## Запуск

### Локально

```bash
cp .env.example .env
# отредактируйте .env: BOT_TOKEN обязателен, OPERATOR_* — перед запуском для людей
make run
```

### Docker

```bash
cp .env.example .env
make docker-up     # сборка и запуск в фоне
make docker-logs   # логи
make docker-down   # остановка
```

Данные лежат в `./data/users.json` на хосте — переживают пересборку образа.

### Переменные окружения

| Переменная | Обязательна | По умолчанию | Назначение |
|---|---|---|---|
| `BOT_TOKEN` | да | — | токен от @BotFather |
| `ADMIN_IDS` | нет | пусто | ID админов через запятую |
| `DATA_FILE` | нет | `data/users.json` | путь к файлу профилей |
| `BROADCAST_DELAY_MS` | нет | `60` | пауза между сообщениями рассылки |
| `WEBHOOK_URL` | нет | пусто | пусто — long polling. Иначе публичный https-адрес вебхука, например `https://bot.example.ru/telegram/webhook` |
| `WEBHOOK_SECRET` | да, если вебхук | — | секрет, которым Telegram подписывает каждый запрос |
| `WEBHOOK_LISTEN` | нет | `:8080` | адрес HTTP-сервера бота (HTTPS обеспечивает nginx/Caddy) |
| `WEBHOOK_PATH` | нет | `/telegram/webhook` | путь обработчика; `/healthz` — проверка живости |
| `PRACTICE_URL` | нет | `https://t.me/restquiz_bot/practice` | ссылка на практику, если не задан `PRACTICE_AUDIO` |
| `PRACTICE_AUDIO` | нет | `assets/practice.mp3` | аудиофайл практики: бот пришлёт его прямо в чат по кнопке практики |
| `WELCOME_PHOTO`, `QUESTION_PHOTO`, `QUESTION_PHOTO_1…5` | нет | см. «Картинки» | картинки |
| `OPERATOR_NAME`, `OPERATOR_CONTACT`, `POLICY_URL` | **да для продакшена** | пусто | реквизиты оператора и ссылка на политику для текста согласия |
| `COLLECT_PHONE` | нет | `true` | просить ли номер телефона после согласия |
| `DATA_RETENTION_DAYS` | нет | `365` | срок хранения профиля, 0 — без автоудаления |

Принимается и старое имя `TELEGRAM_BOT_TOKEN` / `ADMIN_ID` — для совместимости.

## Разработка

```bash
make test-race   # тесты с детектором гонок
make vet         # статический анализ
make fmt         # форматирование
make lint        # vet + test
```

Покрыто тестами: логика подсчёта (единственный победитель, равенство двух и трёх
категорий, нехватка ответов, невалидный ввод), чтение конфигурации, сохранение
и перезагрузка профилей, нормализация логина, определение заблокированного бота.

## Что стоит доработать перед продакшеном

- **Ссылка на практику.** Задайте её в `.env` переменной `PRACTICE_URL=https://…` —
  пересобирать код не нужно. Значение по умолчанию находится в
  `internal/quiz/copy.go` (`DefaultPracticeURL`).
- **Хранилище.** JSON подходит для сотен пользователей. Дальше — PostgreSQL:
  интерфейс `Store` уже изолирован, менять придётся только его реализацию.
- **Тексты политики.** Текст согласия в `internal/quiz/consent.go` — рабочий черновик.
  Юридически значимая формулировка должна быть утверждена; при необходимости
  добавьте ссылку на полную политику обработки персональных данных.
- **Вебхук вместо long-polling** при высокой нагрузке: задайте `WEBHOOK_URL` и `WEBHOOK_SECRET`, пробросьте порт `8080` за HTTPS-прокси.
- **Юридическая часть**: уведомление в Роскомнадзор, политика ПДн, сервер в РФ — см. `docs/PRIVACY.md`.
